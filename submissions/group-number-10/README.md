# Group Number 10 — Human or AI?

This is a binary text classifier that predicts whether a passage was written by a human (`0`) or generated by AI (`1`).
The metric is **AUROC**, and the Kaggle submission is P(AI) for every `test.csv` ID.

## Final approach

The final submission comes from the transformer fine-tuning track (Marcos; see [its section](#transformer-fine-tuning-marcos--final-model)). The final model is DeBERTa-v3-large, fine-tuned end to end with three changes:

- **`[NL]` token.** Line breaks are replaced by a new `[NL]` token. The tokenizer otherwise drops them, and line layout carries signal.
- **Layout augmentation.** In each epoch, half of the training passages get a random line layout from `src/layout.py`. This keeps the model from using line layout as a shortcut.
- **Training.** lr 1e-5, 3 epochs, 10% linear warmup, batch size 16, max length 512 tokens, fp32.

The model is retrained on all 10,000 labeled rows, keeping the last epoch. Four seeds (42–45) are trained, and their test probabilities are averaged.

| | AUROC |
|---|---|
| Validation (8k/2k split, seed 42, one model) | 0.99942 |
| Kaggle public (4-seed average) | 0.99166 |

## Setup

Python 3.12. A CUDA GPU is needed for the final model: DeBERTa-v3-large at batch size 16 in fp32 peaked at about 51 GB of GPU memory.

```bash
cd submissions/group-number-10
python3.12 -m venv .venv
source .venv/bin/activate
pip install --upgrade pip
pip install -r requirements.txt
```

On Linux with CUDA, install the torch wheel that matches your CUDA version from pytorch.org if the default one doesn't see the GPU.
The device is picked automatically (CUDA → Apple MPS → CPU); `--device` overrides it.

Download the Kaggle files into `data/` (git-ignored):

```text
data/
  train.csv               10,000 labeled (5,000 human / 5,000 AI)
  test.csv                 3,000 Kaggle evaluation passages
  unlabeled.csv            3,000 unlabeled passages (only used for the pseudo-labeling experiment)
  sample_submission.csv    used to check submission IDs and columns
```

Pretrained weights are downloaded from Hugging Face on first use. Our job scripts point `--model-name` at local copies under `models/` (for example `models/deberta-v3-large`). The Hub name gives the same model and the same output file names.

## Validation protocol

All experiments use one fixed stratified split of `train.csv`: **8,000 train / 2,000 validation, seed 42**, stored in `splits/split_seed42.json` with the SHA-256 of `train.csv`.

```bash
python -m src.data verify    # confirm your train.csv matches the committed split
python -m src.data inspect   # optional: format, balance and duplicate checks -> results/data_report.json
```

Each transformer validation run scores the 2,000 held-out rows after every epoch and keeps the epoch with the best validation AUROC. Hyperparameters were chosen on this split only. Because the split chooses both the epoch and the configuration, the reported validation AUROC is slightly optimistic. The CNN comparison evaluates the final epoch, as described below.

## Reproducing the final submission

```bash
python -m experiments.distilbert_full --model-name microsoft/deberta-v3-large --lr 1e-5 --epochs 3 \
  --warmup-ratio 0.1 --newline-marker "[NL]" --layout-aug 0.5 --seeds 42 43 44 45
cp results/submissions/deberta-v3-large_nl_wu0.1_aug0.5_lr1e-05_ep3_bs16_len512_full_seeds42-43-44-45.csv submission.csv
```

- **Outputs:**
  - Per seed: test predictions (`results/submissions/<run>_seed<N>_full.csv`), config and training history (`results/full/<run>_seed<N>_full.json`), and model (`checkpoints/full/`).
  - The seed average, which is checked against `sample_submission.csv`.
- **Resumable:** a seed whose test predictions already exist is loaded instead of retrained.
- **Time:** about 92 minutes per seed on an NVIDIA GB10, so about 6 hours for four seeds.
- **Origin of the Kaggle file:** our submitted file averaged seeds 42–43 and 44–45, trained in two separate calls. That equals the 4-seed average above.
- **Exactness:** GPU kernels aren't bit-for-bit deterministic, so a rerun matches to within small numerical differences, not exactly.

To score a single saved checkpoint instead:

```bash
python predict.py --checkpoint checkpoints/full/<run> --out submission.csv
```

## Seeds and configuration

- **Split:** seed 42 (`splits/split_seed42.json`).
- **Training seeds:** 42 for validation runs; 42, 43, 44 and 45 for the final full-data models.
- **What `set_seed` sets:** Python `random`, NumPy, `PYTHONHASHSEED` and torch. DataLoader shuffling is seeded too.
- **Layout augmentation:** uses `np.random.default_rng([seed, epoch])`.
- **Where each run's config is saved:** every hyperparameter is in its metrics JSON (validation runs) or `results/full/*.json` (final runs), and the run name encodes the main ones (for example `deberta-v3-large_nl_wu0.1_aug0.5_lr1e-05_ep3_bs16_len512_seed42`).
- **Optimizer:** AdamW with weight decay 0.01 (none on bias and LayerNorm), linear warmup then linear decay, gradient-norm clip 1.0.

## Data rules we followed

- The final model sees `test.csv` only to predict it: no training, pseudo-labels or tuning on it. We never tried to recover test labels.
- The logistic regression (not the final submission) uses `test.csv` text, never labels, in two ways:
  - It builds its TF-IDF vocabulary from train, `unlabeled.csv` and `test.csv` text.
  - It chooses the word-feature `C` by AUROC on the 500 validation passages that look most like test. A train-vs-test text classifier picks those passages.
- No external labeled data was used, and no LLM API labeled or predicted any passage.
- Validation rows never entered training in validation experiments.

## Transformer fine-tuning (Marcos) — final model

Code: `src/classifiers/distilbert.py` (classifier for any Hugging Face encoder, despite the name), `src/layout.py`
(line-layout augmentation), `experiments/distilbert_train.py` (one validation run), `experiments/distilbert_full.py`
(final models on all 10k rows). Seed 42, same 8k/2k split as every other model.

I started from DistilBERT and moved to larger pretrained encoders (RoBERTa-large, ELECTRA-large, DeBERTa-v3-base,
-large and v2-xlarge), each fine-tuned end to end with a 2-way classification head. The final submission comes from
this track: DeBERTa-v3-large with the `[NL]` token and layout augmentation, as described in [Final approach](#final-approach).
Reproduction is in [Reproducing the final submission](#reproducing-the-final-submission), and seeds in [Seeds and configuration](#seeds-and-configuration).

### Fixed settings

- AdamW, weight decay 0.01, linear decay, gradient-norm clip 1.0. Large models also warm up linearly over the first 10% of steps; DistilBERT has no warmup.
- Batch size 16, max length 512 tokens, fp32 (bf16 only for DeBERTa-v2-xlarge).
- Each validation run keeps the epoch with the best validation AUROC; final full-data runs keep the last epoch.

### Commands

Each run of `experiments.distilbert_train` writes:
- `results/metrics/<run>.json`: config, seed, per-epoch losses and AUROC, train/val metrics.
- One row in `results/distilbert_experiments.csv`.
- Validation predictions in `results/predictions/` (git-ignored).

```bash
# final recipe on the validation split (val AUROC 0.99942)
python -m experiments.distilbert_train --model-name microsoft/deberta-v3-large --lr 1e-5 --epochs 3 \
  --warmup-ratio 0.1 --newline-marker "[NL]" --layout-aug 0.5 --seed 42

# model comparison (same settings without augmentation; swap the model name)
python -m experiments.distilbert_train --model-name microsoft/deberta-v3-large --lr 1e-5 --epochs 3 \
  --warmup-ratio 0.1 --newline-marker "[NL]" --seed 42
python -m experiments.distilbert_train --lr 3e-5 --epochs 4 --newline-marker "[NL]" --seed 42   # DistilBERT

# learning curve: add --train-size N (500, 1000, 2000, 4000, 5000) and --no-checkpoint
# line-break stress test on a saved checkpoint
python -m experiments.format_stress --checkpoints checkpoints/deberta/<run>
# pseudo-labeling from unlabeled.csv, then retrain with the confident labels added
python -m experiments.pseudo_label --name large8k --checkpoints checkpoints/deberta/<run>
python -m experiments.distilbert_train <same flags> --extra-train results/pseudo/large8k.csv
# report figures from the recorded results
python -m experiments.report_figures
```

### Results

Seed 42, AUROC on the 2,000 validation rows:

| Model | Settings | Val AUROC |
|---|---|---|
| DistilBERT (uncased) | lr 3e-5, 4 epochs | 0.99114 |
| DistilBERT + `[NL]` | lr 3e-5, 4 epochs | 0.99889 |
| ELECTRA-large + `[NL]` | lr 1e-5, 3 epochs, warmup 0.1 | 0.99789 |
| RoBERTa-large + `[NL]` | lr 1e-5, 3 epochs, warmup 0.1 | 0.99903 |
| DeBERTa-v3-large, no `[NL]` | lr 1e-5, 3 epochs, warmup 0.1 | 0.99763 |
| DeBERTa-v3-large + `[NL]` | lr 1e-5, 3 epochs, warmup 0.1 | 0.99982 |
| DeBERTa-v3-large + `[NL]` + layout aug 0.5 (final) | lr 1e-5, 3 epochs, warmup 0.1 | 0.99942 |

The final model scores a little lower on validation than the model without augmentation, but it is much more robust to line layout. When validation texts are reformatted into short lines, the model without augmentation calls 821 of 1,000 AI texts human; the final model calls 19. On Kaggle it also scored 0.99166, compared with 0.98460 without augmentation.

## Logistic regression (Joshua)

Code: `logreg/features.py` (text cleaning + feature blocks), `logreg/model.py` (single and stacked
logistic regression), `logreg/ablation.py` (which blocks help), `logreg/stack.py` (stacked model + submission).
Seed 42, same 8k/2k split as every other model.

Feature blocks: word 1-2-gram TF-IDF, char 3-5-gram TF-IDF, 20 style features, 6 GPT-2 log-probability features.
The stacked model trains one logistic regression per block and combines their out-of-fold scores with a
meta logistic regression.

```bash
# from submissions/group-number-10/
python -m logreg.ablation   # one logreg per block combo, C by 5-fold CV -> results/logreg/ablation.json + metrics/
python -m logreg.stack      # stacked model, words-C sweep, test-like check, refit on all 10k
                            # -> results/logreg/stack_sweep.json + submissions/logreg_stacked_wordsC<C>.csv
pytest tests/logreg -q      # logreg unit tests
```

Notes:
- The first run scores every passage with pretrained GPT-2 and caches it to `results/logreg/lm_cache_gpt2.csv`
  (gitignored), so later runs skip it. Without torch/transformers the GPT-2 block is skipped.
- The TF-IDF vocabulary and the test-like check use unlabeled text from `unlabeled.csv` and `test.csv`
  (never test labels).

## Text CNN (Kim)

Code: `cnn.ipynb`

I implemented two models with 128 filters versus 64 filters. Both models use 64-dimensional embeddings, one convolutional layer, kernel size 3, ReLU, global max pooling and a linear output layer.

### Fixed settings

- Stratified training/validation split: 8,000/2,000 examples.
- Split, initialization and batch-shuffling seed: 42.
- Vocabulary: up to 30,000 entries, built from training text only.
- Sequence length: 512 tokens.
- Batch size: 64.
- Optimizer: AdamW, learning rate 0.001, weight decay 0.01.
- Loss: `BCEWithLogitsLoss`.
- Training: 30 epochs on CPU; evaluation uses the final epoch.

### Install and run

Use the shared environment and dependencies from the Setup section. Run from `submissions/group-number-10/`, with the Kaggle files in `data/`:

```bash
python -m src.data verify
python -m IPython -c "%run cnn.ipynb"
```

The notebook prints training AUROC, validation AUROC and training time for each model. The recorded notebook used Python 3.15.1; the shared setup above uses Python 3.12.

### Results

| Filters | Training AUROC | Validation AUROC | Training seconds |
|---|---:|---:|---:|
| 128 | 1.0000 | 0.9613 | 272.12 |
| 64 | 1.0000 | 0.9527 | 162.63 |

Training time excludes preprocessing and final evaluation and depends on the machine.
